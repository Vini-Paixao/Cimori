# Phase 5 tray implementation plan

**Goal:** Port the mod's pinned/overflow tray and native button actions to a normal Windows process.
**Architecture:** UI Automation over the shell notification buttons, supplemented by NotifyIconSettings
metadata and PNG snapshots. Never guess Explorer memory layouts or private callback IDs. Reacquire
buttons before every action; left invokes the button and right clicks its real rectangle. Registry
and UIA events wake a dedicated MTA worker; 3 s refresh only while an island tray panel is open.
**Reference/spec:** Phase 5 request; ROADMAP.md; Mac Island & Dock 3.1.1 TrayIcon/TrayIconKey,
PostTrayIconMessage/PostTrayIconRelease/OpenFromTrayIcon and tray pin/layout behavior.

## Constraints and decisions

- Work only in this existing feat/tray worktree; one final commit, no merge or push.
- Registry alone is historical: correlate snapshots with live UIA or
  running executable paths. Registry-only running-process candidates may include obsolete icon IDs;
  activation must always resolve an unambiguous live button, never start an executable.
- Opening hidden icons can require briefly showing the shell overflow. Do so only on explicit tray
  panel opening or activation, never at idle/startup. Close only overflow opened by this worker.
- Preserve the running installed island; use a diagnostic CLI mode for isolated enumeration.
- Desktop access may be unavailable in this sandbox: report this separately from native API success.
